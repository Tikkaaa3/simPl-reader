# Reader-workload fixture package

This directory contains the pinned input package for the Iced reader prototype.
It is a test workload, **not** a production document representation or a
decision about the fonts/assets to ship in the final reader.

## Contents

- `manifest.txt` — machine-checkable asset manifest (generated): every
  font/image/license/reference file with its relative path, SHA-256,
  version/revision, provenance, and license/notice path.
- `assets/fonts/` — six pinned, unmodified Noto binaries (OFL-1.1):
  Latin regular/bold/italic static hinted TTFs, Arabic and Hebrew static
  hinted TTFs, and the `NotoSansJP[wght].ttf` variable font (axis wght;
  the file's intrinsic default is 100/Thin — the fixture baseline
  explicitly requests the `wght=400` instance).
- `assets/images/reader-sample.png` — project-authored 480×320 PNG,
  deterministically generated by `tools/generate_sample_png.py`.
- `licenses/` — complete license/notice texts for every third-party
  asset (OFL texts per font family, Unicode License for the BiDi test
  excerpt) and an honest project-authored notice for the rest.
- `references/BidiCharacterTest-excerpt.txt` — verbatim excerpt from the
  Unicode 17.0.0 conformance file (lines 47, 48, 49, 142, 144, 230, 231,
  250, 251, 252, 253) used as the pinned BiDi ordering reference.
- `references/bidi-reference.md` — visual-correctness case table with
  pinned sources (Unicode 17.0.0, UAX #9 rev 51) and explicit non-claims.
- `references/selection-cases.md` + `references/expected-copy/*.txt` —
  named selection/copy cases and independent golden expected strings.
- `tools/build_fixture_data.py` — authoring-time generator for
  `curated.rs`, `selection_cases.rs`, the manifest, the case table, and
  the golden files. Not part of the Rust library or its tests; normal
  generation and verification never run it and never touch the network.
- `tools/generate_sample_png.py` — generator provenance for the PNG.

## Canonical bytes across checkouts

A fixture-local `.gitattributes` (this directory only) pins LF-only text
and binary fonts/PNG, so a fresh Windows checkout with either
`core.autocrlf` setting yields byte-identical files and the manifest
checksums keep matching. An isolated fresh-checkout regression test
(`crates/reader-workload/tests/fresh_checkout.rs`) verifies both
settings without touching global Git configuration.

## Fixture revision

`reader-workload-fx-3` stamps the manifest and every workload the
library generates. Changing curated content, an asset, or a golden file
means changing the fixture revision (edit
`tools/build_fixture_data.py`, rerun it once) so later measurements can
identify their exact inputs.

## Path conventions

All manifest paths are portable, fixture-root-relative paths. The
fixture root is the `fixtures/reader-workload` directory located at the
repository root; consumers resolve it by walking up from any directory
inside the repository until `fixtures/reader-workload/manifest.txt` is
found (`reader_workload::manifest::find_fixture_root`). No committed
file contains machine-specific absolute paths, and no asset loading
happens implicitly: the Iced adapter explicitly loads fonts/images after its
shell frame, using the manifest.

## Offline behavior

Everything here was vendored from official upstreams during
implementation and is committed locally. Normal usage — workload
generation, tests, asset validation — performs no network access, no
font installation, and no system-font fallback for the controlled
baseline. Third-party fonts were downloaded once from official upstream
repositories; the manifest pins the exact revisions.

## Shared layout recipe

The single source for the shared layout/font inputs (DIP units, 800 and
480 content widths, 600 viewport height, body 18/27, heading 28/38,
paragraph gap 12, image display 240×160) is the Rust library:
`crates/reader-workload::recipe` (`LAYOUT_RECIPE`). It is a PoC test
input, not a product UI default.

## Current limits

- The fixture includes Arabic/Hebrew mixed-direction passages, Japanese text,
  decomposed combining sequences, and English passages with Latin style runs;
  rendering and clipboard behavior must be checked in the consuming UI.
- File presence/integrity is machine-checked here. Actual glyph rendering,
  fallback, and clipboard results belong to the consuming UI's checks, not
  this fixture specification.
- The workload structure is not a production document AST or locator
  contract.
